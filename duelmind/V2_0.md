# DUELMIND V2.0 — ISOBAR V2.0.2

## 원인

V1.5 Executor는 패·필드에 V2 신규 카드 214~216을 등록하지 않았고, Python 결정 서버가 응답하지 않을 때 `TryDecideMainPhase`가 `null`을 반환했다. 이 경우 WindBot 기본 로직이 전개 후보를 다시 선택하지 못해 합법적인 중앙관측소 발동·특수 소환이 남아 있어도 턴 종료로 빠질 수 있었다.

## 변경

- 시러스, 님버스, 폭풍경계를 카드 상수와 Executor 후보에 등록했다.
- 중앙관측소와 후속 카드가 합법 후보로 제공되면 Python 응답이 없을 때도 중앙관측소 → 아르젠/시러스 → 레인/노바/제피르/님버스 → 엑시즈 → 배틀 → 엔드 순서의 로컬 합법 fallback을 사용한다.
- 메인 페이즈에 선택 후보가 없거나 fallback이 실행된 사실과 선택 카드 ID를 `%TEMP%\duelmind-windbot.log`에 기록한다.
- Python 엔진에 V2 카드 ID와 시러스·님버스·폭풍경계 점수를 추가하고, 필드가 없을 때 초동 카드가 남아 있으면 `end_phase`를 강하게 억제한다.
- WindBot 덱을 V2.0.2 40장/15장 구성으로 교체했다.

## 검증

- Python/IPC/회귀 테스트 34개 통과.
- `py_compile` 통과.
- 사용자 전용 .NET SDK 8.0.427을 설치하고 `DuelmindIsobarExecutor.csproj`를 설치된 `WindBot.dll`/`ExecutorBase.dll`에 참조해 빌드했다. 별도 Executor DLL 빌드 결과는 `duelmind/windbot/bin/Release/net8.0/DuelmindIsobarExecutor.dll`이다.
- 설치본은 외부 Executor DLL을 자동 로드하지 않고 Executor가 `WindBot.dll`에 내장되는 구조였다. 따라서 WindBot 원본에 V2 소스와 GameAI 브리지를 포함해 self-contained `win-x64` 번들을 다시 publish했고, reflection으로 설치된 `WindBot.dll`에 `FallbackMainPhaseAction`과 V2 `TryDecideMainPhase`가 포함된 것을 확인했다.
- 기존 설치본은 `.backups/windbot-before-v2-20261107_211759`에 백업했다.
- 실제 설치 경로: `C:\Users\bduid\Games\EDOPro\ProjectIgnis\WindBot`.
- 실제 EDOPro 듀얼은 EDOPro 창 포커스가 작업 중 ChatGPT로 전환되어 안정적으로 조작하지 못했으므로 통과로 보고하지 않는다.

## 설치

```powershell
$edo = 'C:\Users\bduid\Games\EDOPro\ProjectIgnis'
Copy-Item .\duelmind\windbot\AI_DuelmindIsobar.ydk "$edo\WindBot\Decks\AI_DuelmindIsobar.ydk" -Force
python .\duelmind\server.py
```

별도 Executor API 확인용 프로젝트는 다음처럼 빌드한다.

```powershell
$env:DOTNET_CLI_HOME = "$PWD\.dotnet-cli-home"
$env:APPDATA = "$env:DOTNET_CLI_HOME\Roaming"
$env:USERPROFILE = $env:DOTNET_CLI_HOME
& 'C:\Users\bduid\.dotnet8\dotnet.exe' build .\duelmind\windbot\DuelmindIsobarExecutor.csproj -c Release -p:EDOPRO_ROOT=$edo --configfile .\duelmind\windbot\NuGet.Config
```

실제 WindBot 번들은 WindBot 원본 소스에 `DuelmindIsobarExecutor.cs`를 포함한 뒤 `net8/WindBot.csproj`를 `win-x64`, self-contained로 publish해야 한다. 설치 후 `%TEMP%\duelmind-windbot.log`에서 `DUELMIND executor activated; native C# bridge loaded`를 확인한다. Python 서버가 없으면 Executor의 합법 fallback이 중앙관측소 발동 → 몬스터 전개 → 엑시즈 → 배틀 → 종료 순서로 동작한다.

기존 V1/V2.0.1 실행 파일은 교체 전에 별도 백업해야 한다. `main`에는 병합하지 않는다.
