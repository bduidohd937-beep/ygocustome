# DUELMIND V2.1 — Strategic Decision Engine

## 감사 결과

V2.0은 EDOPro/WindBot이 제공한 합법 행동을 Python 엔진에 전달하고, Python이 `action_id`를 고른 뒤 C#이 그 인덱스를 반환하는 구조였다. 기존 문제는 후보 전체가 아닌 상위 점수 일부만 로그에 남았고, 후보 카드명이 없었으며, Python이 중단되면 C# 로그에는 원인과 실제 fallback 후보가 충분히 남지 않았다는 점이었다.

현재 `%TEMP%\duelmind-windbot.log`에는 재현 가능한 실전 로그가 없었다. 따라서 기존 일반 소환 → 효과 → 엑시즈 → 세트 → 종료 순서는 소스의 Executor 등록 순서와 fallback 순서로 감사했으며, 실제 듀얼에서 관찰된 개선으로 주장하지 않는다.

## V2.1 변경

- `duelmind/strategy.json`에 즉시 이득, 검증된 후속 전개, 상대 견제력, 자원 보존, 필드 지속성, 승리 기여도, 기상 연계 가중치를 분리했다. 값은 0~3 범위로 제한된다.
- Python 응답에 모든 합법 후보의 카드 ID, 카드명, 행동 유형, 위치, 점수, 점수 이유, 순위를 추가했다. 기존 `ranked` 축약 필드는 호환성을 위해 유지한다.
- C# Executor가 턴, 페이즈, 후보 카드명, 후보 ID, 최종 선택, Python 선택 여부, fallback 원인, 실행 반환 결과를 `%TEMP%\duelmind-decisions.jsonl`에 기록한다.
- 설치된 WindBot API가 노출하지 않는 Lua 기상 플래그는 `weather: "unknown"`으로 명시한다. 임의로 기상을 추정하지 않으며, 향후 엔진 어댑터가 값을 공급할 수 있다.
- 실제 카드 효과에 근거한 검증 평가만 C#에서 부여한다. 중앙관측소는 후속 전개·기상 연계를, 아르젠/관측일지는 후속 자원을, 스톰바스티온/템페스트 제로/긴급경보는 견제력을, 솔라 호크는 자원 보존과 후속을 높인다.
- 검증된 평가 메타데이터가 없는 미래 상태는 시뮬레이션하지 않는다. Python은 EDOPro가 제공한 현재 합법 후보만 선택한다.
- Python 연결 실패 시 기존 합법 fallback을 유지하고, 해당 원인을 JSONL에 기록한다.

## 검증

- Python 문법 검사: 통과
- 기존 + V2.1 테스트: 38/38 통과
- Decision Trace 실제 JSONL 요청: 통과. 중앙관측소 후보가 카드명·점수·이유와 함께 기록됨을 확인했다.
- `DuelmindIsobarExecutor.csproj`를 설치된 WindBot DLL/ExecutorBase DLL에 참조해 빌드: 성공, 오류 0
- V2.1 Executor를 WindBot 원본에 포함한 `win-x64` self-contained 전체 publish: 성공, 오류 0. upstream 기존 경고만 존재.
- 설치본 교체: 수행하지 않음. 사용자 요청대로 별도 승인 전에는 현재 EDOPro 설치본을 보존한다.
- 실제 EDOPro 듀얼, 실제 중앙관측소 발동, 실제 선공/후공 반복 듀얼: 미실행
- 실제 C# Executor와 실행 중 EDOPro 사이의 live IPC: 미실행. Python 서버 단독 IPC 및 fallback 경로는 자동 테스트/소스 검증까지만 수행했다.

## 실행·진단

```powershell
python .\duelmind\server.py
```

Decision Trace는 다음 파일에 JSONL로 기록된다.

```text
%TEMP%\duelmind-decisions.jsonl
%TEMP%\duelmind-windbot.log
```

## V2.2 제안

1. WindBot 어댑터가 `ISOBAR.FLAG`의 실제 기상 상태를 공개 상태에 전달한다.
2. EDOPro replay 자동화로 중앙관측소·아르젠·솔라 호크·스톰바스티온·템페스트 제로의 6개 대표 시나리오를 반복 실행한다.
3. 실제 실행 결과를 JSONL의 `execution_result`에 연결해 선택 성공과 엔진 거부를 구분한다.
