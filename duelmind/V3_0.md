## 범위

V3.0은 V2.2의 이소바르 판단 엔진과 JSONL IPC를 보존하면서, 덱 프로필을 명시적으로 선택하는 범용 진입점을 추가한다.

## 구조

| 영역 | 역할 |
| --- | --- |
| `duelmind/core/` | 덱 공통 계약과 안전 fallback |
| `duelmind/profiles/` | 덱 프로필, 카드 ID 범위, 구현 상태, 필요한 입력 |
| `duelmind/planner/` | 프로필별 목표 계약. 미구현 프로필은 계획을 만들지 않음 |
| `duelmind/adapters/` | WindBot 덱 이름을 명시적 `deck_profile`로 변환 |
| `duelmind/engine.py` | V2.2 이소바르 판단과 프로필 dispatch의 호환 진입점 |

새 WindBot 요청은 최상위에 `deck_name`과 `deck_profile`을 보내며, `public_state`에도 같은 값을 기록한다. Python은 이 값을 우선한다. V2.2 이전 요청처럼 프로필이 없으면 기존 이소바르 동작을 유지하고 `profile_status=legacy_compatibility`를 기록한다.

## 프로필 상태

### 이소바르

`isobar` 프로필은 `210000201`부터 `210000216`까지를 등록하고, 기존 V2.2 전략 엔진으로 보낸다. 기존 카드별 효과 식별자, 합법 행동 제한, Decision Trace 필드는 유지된다.

### 오션테일

저장소와 확인 가능한 Git 참조에서 오션테일의 실제 카드 ID, 카드 DB 항목, Lua 스크립트, 효과 원문 또는 덱 리스트를 찾지 못했다. 따라서 카드를 창작하거나 이소바르 규칙을 재사용하지 않고 `ocean_tale`을 `implemented=false`로 등록했다.

구현에 필요한 입력:

1. 실제 카드 ID와 카드명
2. `cards.json` 또는 `.cdb` 카드 데이터
3. 카드 효과 원문과 Lua 스크립트
4. 메인/엑스트라 덱 리스트와 매수
5. WindBot 덱 등록명 및 Executor 연결 정보

오션테일 요청은 합법 행동 목록 안에서 `pass` 또는 `end_phase`를 우선하는 안전 fallback만 사용하고, 후보에 임의의 점수나 콤보를 부여하지 않는다.

## 호환성 및 제한

- 기존 V2.2 IPC의 `protocol=duelmind.v1`과 `action_id` 반환 형식을 유지한다.
- 새 덱은 카드 ID로 추정하지 않는다. 명시적 프로필이 없고 덱 이름도 없으면 `unknown`으로 처리한다.
- Python이 반환하는 것은 선택한 합법 행동이며, 실제 효과 해결은 WindBot/EDOPro가 수행한다.
- 설치본 교체 및 실제 EDOPro 듀얼은 이 변경에 포함하지 않았다.
